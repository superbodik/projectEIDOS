# Карта модулей

Разбиение крупных файлов (2446 и 1649 строк) на тематические подмодули.
**Поведение не менялось** — это чисто механический перенос кода: функции
переехали в новые файлы построчно, без единой правки внутри тела функций.
После каждого шага прогонялась полная регрессия (`geocheck`, `biomecheck`,
`placecheck`, `mouthcheck`, `orecheck`, `toolcheck`, `rivercheck`,
`rulescheck`) — везде 0 расхождений с поведением до разбиения.

Заголовочные файлы (`.h`) остались на прежнем месте — их подключает
код по всему проекту, и перенос заголовков потребовал бы правки путей
`#include` везде, где они используются, а не только в самих модулях.
Только `.cpp`-реализации разложены по подпапкам.

## Как проверялось «ничего не изменилось»

Для каждого разбиения:
1. Точные границы функций находились построчным поиском (`grep -n`), а не
   на глаз — с явной сверкой, что строка N действительно начинает нужную
   функцию.
2. Перенос кода — построчное копирование через Python (`lines[a:b]`),
   а не ручной набор текста, чтобы исключить опечатки при переносе тысяч
   строк.
3. После каждого переноса — проверка, что каждая исходная функция
   встречается **ровно один раз** среди всех новых файлов (ни одна не
   потерялась, ни одна не задвоилась).
4. Проверка баланса фигурных скобок в каждом новом файле (защита от
   разреза посреди функции — так был пойман один реальный баг: закрывающая
   скобка деструктора `EidosEngine::~EidosEngine()` при первом разрезе
   попала в файл `Panorama.cpp` вместо `EidosEngine.cpp`, компилятор
   поймал сразу).
5. Полная пересборка движка и всех 8 валидаторов после каждого файла,
   не пачкой в конце.
